# ADR-0001: SQLite в первой итерации

Дата оформления: 2026-10-25. Статус: **Принято**.

Происхождение: прямое уточнение пользователя — в перспективе задача может включать собственный движок и приложение, но начать следует с SQL БД SQLite.

## Контекст

Исходное «база данных с нуля» допускает два разных объёма: написать приложение или также разработать движок хранения. Учебная первая версия должна сохранять имена и телефоны, поддерживать поиск и два способа доступа. Масштаб — тысячи записей. Разработка движка добавляет отдельную задачу сохранности и восстановления данных.

## Решение

В первой итерации используем файловую SQLite через модуль Python `sqlite3`. Собственный движок в эту итерацию не включаем. Возможность его создания сохраняем как направление дальнейшей работы, без обязательства реализовать его или поддержать совместимость с файлами SQLite.

## Альтернативы

- **Собственный движок сразу:** соответствует расширительному толкованию исходного текста, но увеличивает объём первой итерации. Пользователь отложил этот вариант.
- **Отдельный SQL-сервер:** добавляет установку и обслуживание сервера, потребность в которых текущими требованиями не задана.
- **Файл JSON или CSV:** потребовал бы самостоятельно определить безопасную запись, восстановление и поиск. Для первой версии уже выбрана готовая SQL БД.

Эти варианты не сравнивались нагрузочными испытаниями; решение основано на объёме задачи и выборе пользователя.

## Последствия

Приложение может использовать готовые транзакции и SQL. При этом его реализация остаётся зависимой от SQLite и её поведения. Сам выбор технологии не доказывает выполнение гарантий: нужны проверки ошибок записи, перезапуска и аварийного завершения.

Будущий движок потребует отдельного решения о переносе данных, гарантиях и приёмке.

## Когда пересмотреть

Если обучение перейдёт к разработке движка либо появятся требования к другим условиям размещения или нагрузки. Число 10 000 само по себе не является порогом обязательной смены БД.

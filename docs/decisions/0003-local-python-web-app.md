# ADR-0003: Локальное Python-приложение с браузером и HTTP API

Дата оформления: 2026-10-25. Статус: **Принято**.

Происхождение: при отсутствии предпочтений пользователя выбраны Python и интерфейс в браузере с HTTP API. Flask и простой интерфейс HTML/CSS/JavaScript выбраны автором при техническом проектировании.

## Контекст

Нужны визуальный и программный доступ к одним данным с одинаковыми правилами. Первая версия предназначена для одного пользователя на одной машине. Предпочтений по языку и виду окна пользователь не высказал.

## Решение

Используем Python, Flask и браузерный интерфейс без отдельной сборки. Один процесс выдаёт страницу и JSON API; браузер обращается к тому же API, что и внешняя программа. Приложение слушает локальный адрес 127.0.0.1; отладчик отключён. Операции и ошибки API определены в design.md.

## Альтернативы

- **Настольное окно:** возможно, но потребовало бы другого интерфейса и отдельного решения о программном доступе. Текущая задача допускает общий HTTP API.
- **Отдельное приложение интерфейса со своей сборкой:** добавляет инструменты и зависимости для небольшого числа форм.
- **Другой язык или веб-фреймворк:** допустимы, однако явного требования к ним нет. Текущий выбор не основан на сравнительном измерении всех вариантов.

## Последствия

Один HTTP-контракт обслуживает оба способа доступа. Для работы нужны локальный процесс Python и браузер. Даже локальный интерфейс должен обрабатывать ошибки связи, потерянные ответы и безопасно отображать введённый текст.

Доступ через Интернет и учётные записи не входят в текущую архитектуру. Их добавление потребует пересмотра требований к размещению и доступу.

## Когда пересмотреть

Если понадобятся настольная интеграция, несколько пользователей, удалённое размещение либо интерфейс, для которого простой страницы недостаточно.

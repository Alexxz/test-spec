# ADR-0004: Подтверждение сохранения после commit

Дата оформления: 2026-10-25. Статус: **Принято**.

Происхождение: техническое решение для принятых гарантий сохранности; поведение при потере ответа уточнено при разборе CUJ-3. Это фиксирует существующий контракт первой версии.

## Контекст

Пользователь должен доверять подтверждению сохранения. Процесс может завершиться во время записи, а HTTP-ответ может потеряться уже после её завершения. Совпадение полных пар разрешено, поэтому повтор запроса может создать ещё одну запись.

## Решение

Создаём запись в транзакции SQLite и возвращаем успех только после commit — фиксации транзакции. Выбраны журнал DELETE и synchronous=FULL; настройки и проверки сохранности описаны в design.md. Гарантия покрывает сбой процесса на исправном носителе.

Если ответ потерян или истёк срок ожидания, интерфейс сообщает неопределённый исход и не повторяет POST автоматически. Он сохраняет введённые значения и предлагает поиск. Во время незавершённого запроса повторная отправка той же формы блокируется. Гарантию однократного выполнения при потере ответа первая версия не предоставляет.

## Альтернативы

- **Подтверждать до фиксации:** создаёт риск потери уже подтверждённой записи и противоречит требованиям.
- **Автоматически повторять POST:** без учёта идентичности операции может создать дубликат.
- **Добавить ключ идемпотентности:** такой идентификатор позволил бы распознавать повтор одной операции, но требует дополнительного контракта и хранения результатов операций. Отложено за пределы первой версии.
- **Запретить одинаковые пары:** меняет принятое правило данных и не различает намеренный повтор и повтор из-за сбоя связи.

## Последствия

Подтверждённые записи должны переживать перезапуск и принудительное завершение процесса. Это проверяется отдельно, а не выводится только из настроек SQLite.

Поиск существовавшей раньше пары не доказывает успех последней операции. Пользовательский повтор после неопределённости может создать ещё одну запись. Отключение питания, потеря диска и резервное копирование остаются за границами гарантии.

## Когда пересмотреть

Если появится требование безопасно повторять создание при сбоях связи или покрывать дополнительные виды отказов. Тогда нужны новая запись решения, изменение API и новые проверки.

# Spec Delta

## Purpose

Хранение пар «имя — телефон» и однозначный поиск связанных записей в обоих направлениях. Правила данных приняты при обсуждении; происхождение решений описано в review.md.

## ADDED Requirements

### Requirement: Создание записи

Система MUST позволять создать запись с именем и телефоном и возвращать её постоянный уникальный идентификатор. Разные записи MUST иметь разные идентификаторы, в том числе при совпадении полей.

#### Scenario: Успешное создание
- **WHEN** пользователь создаёт запись с именем `Анна` и телефоном `+79991234567`
- **THEN** система подтверждает создание и возвращает идентификатор, имя и телефон
- **THEN** запись доступна при поиске по имени и телефону

#### Scenario: Повторная пара
- **WHEN** дважды успешно создаётся одна и та же пара имени и телефона
- **THEN** существуют две записи с различными идентификаторами

### Requirement: Правила входных данных

Система MUST принимать имя и телефон как строки и удалять окружающие пробелы U+0020. Имя MUST содержать символ, для которого Python str.isspace() возвращает False. Телефон MUST целиком соответствовать выражению `[+]?[0-9]{1,15}` после удаления окружающих пробелов. Неверный ввод MUST отклоняться без создания записи.

#### Scenario: Удаление окружающих пробелов
- **WHEN** создаётся запись с именем ` Анна ` и телефоном ` +79991234567 `
- **THEN** сохраняются `Анна` и `+79991234567`

#### Scenario: Сохранение ведущих нулей
- **WHEN** создаётся запись с телефоном `00123`
- **THEN** сохраняется строка `00123`

#### Scenario: Неверные данные
- **WHEN** имя состоит только из пробелов либо телефон содержит буквы, дефисы или более 15 цифр, либо поле отсутствует или не является строкой
- **THEN** система возвращает ошибку проверки данных и не создаёт запись

#### Scenario: Пробельное имя
- **WHEN** имя пусто либо состоит только из табуляций, переводов строки, U+0020 или неразрывных пробелов U+00A0
- **THEN** система возвращает ошибку проверки данных без создания записи

#### Scenario: Обрезка ограничена обычным пробелом
- **WHEN** имя содержит буквы и табуляцию либо U+00A0 по краям
- **THEN** эти символы сохраняются и участвуют в точном сравнении; удаляются только окружающие U+0020

### Requirement: Поиск телефонов по имени

Система MUST возвращать все записи с точным совпадением имени после удаления окружающих пробелов U+0020 из запроса. Сравнение MUST учитывать регистр и внутренние пробелы. Каждая найденная запись MUST содержать идентификатор, имя и телефон; порядок результатов не определён.

#### Scenario: Несколько телефонов
- **WHEN** существуют записи `Анна / +79991111111` и `Анна / +79992222222` и выполняется поиск по имени `Анна`
- **THEN** результат содержит обе записи

#### Scenario: Частичное совпадение и регистр
- **WHEN** существует только имя `Анна` и выполняется поиск по `анна` или `Ан`
- **THEN** результат пуст

### Requirement: Поиск имён по телефону

Система MUST возвращать все записи с точным совпадением телефона после удаления окружающих пробелов U+0020 из запроса. Каждый результат MUST содержать идентификатор, имя и телефон; порядок результатов не определён.

#### Scenario: Общий телефон
- **WHEN** существуют записи `Анна / +79991111111` и `Борис / +79991111111` и выполняется поиск по `+79991111111`
- **THEN** результат содержит обе записи

#### Scenario: Отсутствие автоматического преобразования
- **WHEN** существует только телефон `+79991111111` и выполняется поиск по `79991111111`
- **THEN** результат пуст

### Requirement: Пустой результат и неверный запрос

Система MUST возвращать пустой список при отсутствии совпадений. Пустой или неверный по правилам соответствующего поля поисковый запрос MUST возвращать ошибку проверки данных. Поиск MUST сохранять данные без изменений.

#### Scenario: Совпадений нет
- **WHEN** выполняется корректный поиск в пустом справочнике
- **THEN** возвращается пустой список без ошибки

#### Scenario: Запрос пуст
- **WHEN** поисковая строка пуста или содержит только пробелы
- **THEN** возвращается ошибка проверки данных, данные справочника не изменяются

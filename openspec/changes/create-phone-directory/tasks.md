# Tasks

## 1. Окружение и запуск

- [ ] 1.1 Создать структуру Python-приложения с Flask, настроить зависимости приложения и проверок (pytest, Playwright для браузера), зафиксировать версии; проверить установку и импорт в чистом окружении.
- [ ] 1.2 Добавить настройки пути SQLite и порта, локальный запуск без отладчика; описать команды в README и проверить открытие стартовой страницы по ним.

## 2. Правила справочника

- [ ] 2.1 Реализовать проверку типов, имени, телефона и поисковых запросов; тестами проверить сценарии directory-records, окружающие пробелы U+0020, ведущие нули, граничные длины телефона и пустой ввод.
- [ ] 2.2 Определить границу хранения для создания и двух видов поиска; проверить прикладные правила с тестовой реализацией хранения без SQLite.

## 3. SQLite и сохранность

- [ ] 3.1 Создать файловую схему с постоянными ID, неуникальными индексами и точным сравнением; тестами проверить повторные пары, несколько совпадений, регистр, внутренние пробелы, Unicode и закрытие соединений.
- [ ] 3.2 Добавить транзакционное создание, подтверждение после commit и обработку ошибок; выполнить проверки перезапуска, SIGKILL, остановки до и после commit, SQLITE_FULL по design.md. Проверить сохранность старых записей и продолжение работы после устранения ошибки.
- [ ] 3.3 Описать в README путь данных и границы гарантий; проверить повторный запуск с тем же файлом без потери данных и ошибку запуска без пересоздания существующей БД.

## 4. HTTP API

- [ ] 4.1 Реализовать POST и два вида GET по контракту design.md; тестами проверить коды успеха, строки ID, все совпадения, пустой список, кодирование плюса, неизвестные и повторные параметры, неверный JSON и тип тела.
- [ ] 4.2 Реализовать единый JSON ошибок на адресах API; проверить статусы 400, 415, 503, 404, 405 и 500, отсутствие технических подробностей в ответе и отсутствие ложного успеха при ошибке хранения.
- [ ] 4.3 Описать примеры создания и поиска в README; выполнить примеры против запущенного приложения и сравнить ответы с контрактом.

## 5. Браузерный интерфейс

- [ ] 5.1 Реализовать формы создания и поиска, полный список результатов, сообщения об успехе, пустом результате и ошибках; браузерными проверками выполнить сценарии directory-access и убедиться, что введённый HTML отображается текстом.
- [ ] 5.2 Обработать неопределённый исход создания при потере связи без автоматического повтора; браузерной проверкой подтвердить сообщение пользователю и отсутствие повторного POST.
- [ ] 5.3 Проверить общий набор данных в обоих направлениях: создание через API видно в браузере и создание через браузер видно через API; описать пользовательские действия в README.

## 6. Сквозная приёмка

- [ ] 6.2 Проверить создание и поиск 10 001-й записи, отсутствие программного ограничения на 10 000 и сохранность данных после перезапуска приложения с этим набором.
- [ ] 6.3 Сопоставить все сценарии трёх спецификаций с результатами проверок, выполнить весь набор проверок приложения и строгую валидацию OpenSpec; сохранить команды воспроизведения и результаты.

# Fact Grounding: основания утверждений

Дата проверки: 2026-10-25. Объект: требования, технический проект, ADR и план приёмки первой версии.

## Как читать результат

Fact Grounding означает, что для существенного утверждения можно назвать основание и границы вывода. В этом проекте используем четыре категории:

| Категория | Пример | Достаточное основание |
| --- | --- | --- |
| Требование пользователя | Начать с SQLite | Исходный текст или прямое уточнение в разговоре |
| Решение проекта | Использовать Flask | Запись о выборе и причинах; внешняя статья не может выбрать за нас |
| Технический факт | BINARY различает регистр | Первичная документация, при необходимости воспроизводимый эксперимент |
| Требование к будущей реализации | Поиск за одну секунду | Измерение готового приложения; до него это критерий, а не достигнутый результат |

Статус «подтверждено документацией» относится только к сформулированному свойству инструмента. «Наблюдалось локально» относится только к записанным версиям и примерам. Они не означают, что будущее приложение уже удовлетворяет требованиям.

Ссылки на ADR и review.md ведут к записи решений, сделанной в ходе этой сессии, а не к независимому экспорту переписки. Внешние источники не подтверждают пользовательские намерения. После LLM-expert review автор сузил имя до одной строки без управляющих символов по ADR-0006. Пользователь попросил сохранить за ним роль дилетанта и не выбирал технические диапазоны символов.

Ограничение телефона до 15 цифр — выбранное правило формата; соответствие стандарту E.164, существование номера и его доступность не заявлены.

## Проверенные технические утверждения

| ID | Утверждение и результат | Источник и границы |
| --- | --- | --- |
| F-01 | SQLite допускает файловую работу без отдельного сервера; sqlite3 доступен в стандартной библиотеке CPython, но может отсутствовать в конкретной сборке | [Python sqlite3, ветка 3.14](https://docs.python.org/3.14/library/sqlite3.html). Локальный импорт выполнен; на машине пользователя потребуется проверка окружения |
| F-02 | Режим транзакций Python sqlite3 нужно задавать явно; commit при autocommit=True не фиксирует явно открытую SQL-транзакцию | [Python 3.12: управление транзакциями](https://docs.python.org/3.12/library/sqlite3.html#transaction-control). При явном SQL BEGIN завершаем SQL COMMIT/ROLLBACK; в реализации выбран режим с методами commit/rollback, описанный в design.md |
| F-03 | application_id и user_version служат маркерами файла; схема и эти маркеры в нашем эксперименте откатывались и сохранялись вместе | [SQLite PRAGMA](https://sqlite.org/pragma.html#pragma_application_id), [user_version](https://sqlite.org/pragma.html#pragma_user_version); локально schema_transaction. Маркеры выбирает проект; они не удостоверяют подлинность файла |
| F-04 | DELETE + FULL нельзя трактовать как безусловную гарантию сохранения последнего commit при потере питания | [SQLite synchronous](https://sqlite.org/pragma.html#pragma_synchronous), [условия атомарной фиксации](https://sqlite.org/atomiccommit.html). Текущая гарантия ограничена сбоем процесса; её реализация ещё требует испытаний |
| F-05 | BINARY различает регистр и разные последовательности Unicode; обычная TEXT-колонка использует affinity, а не строгую проверку входного типа | [SQLite: типы и сравнение](https://sqlite.org/datatype3.html#collating_sequences). Наблюдалось в comparison_and_ids: ведущие нули сохранены, число преобразовано в текст. Проверку типов должен выполнять сервис |
| F-06 | strip с явным обычным пробелом и isspace решают разные задачи; fullmatch проверяет всю строку | [Python str.strip](https://docs.python.org/3.12/library/stdtypes.html#str.strip), [str.isspace](https://docs.python.org/3.12/library/stdtypes.html#str.isspace), [re.fullmatch](https://docs.python.org/3.12/library/re.html#re.fullmatch). Локально python_strings: ASCII-цифры и необязательный плюс приняты, лишние символы и другие алфавиты цифр отклонены |
| F-07 | AUTOINCREMENT предотвращает повторное автоматическое использование ID удалённых зафиксированных строк, но добавляет издержки | [SQLite AUTOINCREMENT](https://sqlite.org/autoinc.html). В эксперименте после удаления ID 5 выдан ID 6. Это не обещание непрерывной нумерации; удаление выполнено только в эксперименте возможностей БД |
| F-08 | max_page_count ограничивает рост файла; в выбранном эксперименте превышение вызвало SQLITE_FULL | [SQLite max_page_count](https://sqlite.org/pragma.html#pragma_max_page_count). Локально full_database: прежняя запись сохранилась, после снятия лимита запись возобновилась. Реальный полный диск и HTTP-обработка этим не проверены |
| F-09 | Индекс может участвовать в плане поиска; это не измерение времени пользовательского пути | [SQLite EXPLAIN QUERY PLAN](https://www.sqlite.org/eqp.html). В локальном примере план использовал records_name. Критерий одной секунды предстоит проверить отдельно |
| F-10 | Стандартное кодирование параметров преобразует литеральный плюс в %2B, а сырой плюс при разборе формы означает пробел | [WHATWG URL: form parsing](https://url.spec.whatwg.org/#application/x-www-form-urlencoded-parsing), [URLSearchParams](https://url.spec.whatwg.org/#urlsearchparams-class). Используем передачу значений через set/append, не сборку строки из пользовательского текста. Браузерный тест пока не выполнен |
| F-11 | Прерывание fetch завершает ожидание клиента, но не обеспечивает откат уже выполненной серверной записи | [WHATWG Fetch: abort fetch](https://fetch.spec.whatwg.org/#abort-fetch). Отсутствие серверного отката — вывод для нашей архитектуры: отдельного протокола отмены в API нет. Проверка потери ответа после commit остаётся в плане CUJ-3 |
| F-12 | Flask поддерживает маршруты, JSON и выдачу страницы; встроенный сервер предназначен для разработки | [Flask Quickstart](https://flask.palletsprojects.com/en/stable/quickstart/). Это подтверждает наличие возможностей, но не совместимость ещё не установленных зависимостей и не скорость приложения |
| F-13 | Читаемые маркеры и схема не заменяют проверку структурной целостности; integrity_check возвращает ok при отсутствии найденных ошибок | [SQLite integrity_check](https://www.sqlite.org/pragma.html#pragma_integrity_check). Локально проверен только исправный файл; обработка повреждения приложением ещё не проверена |
| F-14 | JSON может содержать escape непарного суррогата; локально его передача sqlite3 вызвала UnicodeEncodeError, корректный дополнительный символ сохранился | [RFC 8259, §8.2](https://www.rfc-editor.org/rfc/rfc8259.txt) и python_strings в обновлённом JSON-отчёте. Правило отклонить такое значение с 400 выбрано проектом и требует HTTP-теста |
| F-15 | requestAnimationFrame вызывается до последующих этапов layout/отрисовки, поэтому один callback не доказывает завершённый кадр | [HTML rendering](https://html.spec.whatwg.org/multipage/webappapis.html#update-the-rendering). Два callback после полного DOM — выбранная граница метрики, а не свидетельство физического показа пикселей |
| F-16 | Возврат объекта Response и чтение его тела — разные этапы Fetch | [WHATWG Fetch](https://fetch.spec.whatwg.org/#fetch-method). Срок ожидания должен оставаться активным при чтении JSON; проверка частичного HTTP-ответа остаётся в плане реализации |
| F-17 | Поле HTML text удаляет CR/LF из значения | [HTML Text state](https://html.spec.whatwg.org/multipage/input.html#text-(type=text)-state-and-search-state-(type=search)). Ограничить имена одной строкой и заранее проверять вставку — выбор автора по ADR-0006, а не требование HTML ко всему API |

Документация Python проверена для минимальной ветки 3.12 и актуальной ветки 3.14 по указанным вопросам; реальный запуск эксперимента выполнен только на Python 3.14.4. SQLite и веб-стандарты доступны по обновляемым страницам; здесь зафиксирована дата обращения. Версии зависимостей самого приложения ещё не выбраны и не испытаны.

## Воспроизводимое локальное свидетельство

Скрипт: [tools/check_facts.py](../../../tools/check_facts.py). Сохранённый результат: [fact-grounding-local.json](../../../docs/evidence/fact-grounding-local.json).

```bash
python3 tools/check_facts.py
```

Команда печатает новый отчёт. Чтобы сохранить отдельный прогон, используйте `--output /tmp/fact-grounding-repeat.json`. Запускать из корня проекта с Python 3.12+ и доступным sqlite3. Скрипт создаёт временные файлы и удаляет их после проверки; рабочие данные приложения ему не передаются.

В сохранённом прогоне: Linux x86_64, Python 3.14.4, SQLite 3.46.1, Unicode 16.0.0. Все четыре группы экспериментов завершились успешно. После экспертного разбора python_strings расширен непарным суррогатом, дополнительным символом Unicode и категориями управляющих символов; schema_transaction — результатом integrity_check для исправного файла. Отчёт перезаписан новым прогоном с обновлённой контрольной суммой. JSON содержит время UTC, версии, наблюдения и SHA-256 скрипта — контрольную сумму, позволяющую связать результат с конкретным содержимым файла.

Это эксперименты с возможностями платформы: они не импортируют реализацию справочника, которой пока нет. Скрипт не проверяет SIGKILL, браузер, сетевые ошибки, полную приёмку на минимальной версии Python или производительность.

## Уточнения по результатам проверки

В design.md уточнены явное управление транзакциями, порядок настройки соединения, проверка наличия sqlite3, роль индексов и способ кодирования плюса. В ADR добавлены ссылки на проверенные основания и ограничения. Эти изменения этапа Fact Grounding уточнили реализацию уже выбранных решений. Последующий LLM-expert review добавил F-13–F-17 и уточнил допустимое имя по ADR-0006; это изменение входного контракта явно отражено в спецификациях.

## Поддержка реестра

При новом техническом утверждении записывать источник, дату, применимую версию и предел вывода. Для гипотезы о скорости или надёжности указывать требуемую проверку. При изменении решения обновлять ADR по правилам журнала; при изменении поведения — спецификацию и сценарии. После реализации к строкам выше нужно добавлять ссылки на реальные отчёты, а не заменять статус только на основании мнения рецензента.

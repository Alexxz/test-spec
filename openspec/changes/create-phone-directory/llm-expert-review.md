# LLM-expert review первой версии

Дата: 2026-10-25. Объект: пакет `create-phone-directory`, ADR-0001–0005 и результаты Fact Grounding до этого разбора.

## Как применена практика

LLM-expert review — разбор моделью с заданной предметной точки зрения. В нашем проекте проверяем хранение и надёжность, API и пользовательский интерфейс, затем проверяемость требований. Для каждого замечания нужны пример возможного сбоя, основание и минимальная правка.

Этот разбор выполнен текущей LLM в трёх экспертных перспективах. Отдельные агенты не запускались; это не независимое заключение трёх специалистов. Независимое чтение без истории разговора ранее выполнено в Elephant + Goldfish и описано в своём отчёте. Здесь предмет проверки — технические детали обновлённого проекта после Fact Grounding.

Входные материалы: исходные требования, proposal, три спецификации, design, tasks, CUJ, review, журнал ADR и реестр фактов. Технические основания сверены с первичной документацией, граничные случаи Unicode и результат integrity_check проверены в локальном эксперименте.

## Замечания и решения

| ID | Перспектива | Риск исходного проекта | Решение и статус |
| --- | --- | --- | --- |
| ER-01 | Хранение и надёжность | Маркеры и схема могут читаться при повреждённой таблице или индексе; конкретной проверки содержимого не было | Исправлено: integrity_check один раз при запуске, ожидается единственная строка ok; ошибки останавливают запуск |
| ER-02 | API и данные | JSON может декодироваться в строку с непарным суррогатом; передача её в sqlite3 вызывает UnicodeEncodeError вместо заявленной ошибки ввода | Исправлено: строгая проверка UTF-8 до хранения, ошибка 400 без замены символов; корректные дополнительные символы поддерживаются |
| ER-03 | API и интерфейс | Начало ответа можно принять за завершение; преждевременное снятие таймера оставит чтение тела без срока ожидания | Исправлено: срок охватывает заголовки и тело; обрыв тела не означает успех, поля сохраняются, форма снова доступна |
| ER-04 | Проверяемость и производительность | «Завершение следующего кадра» не задавало точной метрики; один requestAnimationFrame не доказывает завершённую отрисовку | Исправлено: обе отметки внутри страницы, полный DOM и два последовательных callback; условия видимости и ограничения метрики описаны |
| ER-05 | API и удобство | Допустимое многострочное имя может измениться в обычном поле браузера, после чего точный поиск ищет другое значение | Исправлено выбором автора: однострочное имя без управляющих символов, общая серверная проверка и проверка вставки; ADR-0006 |

Замечания имеют среднюю значимость для первой версии: каждое может привести к неверному результату или неоднозначной реализации в конкретной ситуации. Исправления нужны до завершения соответствующих задач, но не требуют смены архитектуры или расширения функций справочника.

## ER-01: Проверка существующего файла

Пример: заголовок и таблица records читаются, но содержимое индекса повреждено. Проверка только маркеров не обнаруживает этого. [SQLite integrity_check](https://www.sqlite.org/pragma.html#pragma_integrity_check) проверяет структурную целостность, включая соответствие индексов таблицам.

В design.md уточнены место и результат проверки. Её выполняем при запуске, а не на каждом поиске. Отказ не должен пересоздавать файл. Это проверка структуры, не достоверности имён и телефонов и не защита от будущего повреждения носителя. В локальном эксперименте проверен только результат для исправной тестовой БД; обработку повреждения предстоит проверить на реализации по задаче 3.3.

## ER-02: Не всякая строка JSON пригодна для хранения

Непарный суррогат — одиночная часть кодирования символа, которая не представляет самостоятельный символ Unicode. Его можно передать escape-последовательностью в JSON. [RFC 8259, §8.2](https://www.rfc-editor.org/rfc/rfc8259.txt) описывает этот случай и проблемы совместимости.

В эксперименте Python принял такой JSON, а sqlite3 выбросил UnicodeEncodeError. Это свидетельство граничного случая платформы, а не тест HTTP-приложения. Теперь спецификация требует отклонить значение как неверный ввод до обращения к хранилищу. Исправление не запрещает эмодзи или другие корректные дополнительные символы Unicode; их сохранение отдельно проверено экспериментом и включено в план приёмки.

## ER-03: Срок ожидания полного ответа

Fetch возвращает объект ответа отдельно от чтения его тела. [WHATWG Fetch](https://fetch.spec.whatwg.org/#fetch-method) описывает эти этапы и отмену чтения тела.

Если заголовки пришли, а тело зависло, интерфейс всё равно должен закончить ожидание. Для создания такой случай остаётся неопределённым исходом: запись могла сохраниться. Задача 5.5 и ветвь CUJ-3 теперь требуют проверки потери или задержки тела после начала ответа. Неверный JSON также не считается подтверждением успеха.

## ER-04: Воспроизводимая метрика браузера

DOM — структура элементов страницы. requestAnimationFrame — callback браузера, выполняемый в цикле обновления отображения. В [HTML rendering](https://html.spec.whatwg.org/multipage/webappapis.html#update-the-rendering) он расположен до пересчёта стилей и layout; один callback не является свидетельством завершённой отрисовки.

В методике сохранены 10 000 записей, 60 поисков и предел 1 000 мс. Уточнены начало, конец и окружение измерения. Полнота результата проверяется по данным и DOM, после установки которого ожидаются два callback. Это выбранная браузерная метрика, не измерение физического показа всех пикселей монитора. Скорость всё ещё не измерена на приложении.

## ER-05: Решение о форме имени

В первой версии имя — одна строка без табуляций, переводов строк и других указанных в спецификации управляющих символов. Это решение автора после просьбы пользователя сохранить за ним роль дилетанта; пользователь не выбирал диапазоны символов. [ADR-0006](../../../docs/decisions/0006-single-line-names.md) фиксирует выбор, альтернативы и последствия.

Это уточнение сужает ранее допустимую форму имени. Предыдущий положительный сценарий с табуляцией заменён отклонением; U+00A0 и внутренние обычные пробелы продолжают сохраняться. Проверяется и создание, и поиск. При вставке текст не должен молча превращаться в другое имя: прежнее значение сохраняется и показывается объяснение.

Факт о поведении поля подтверждён [HTML Text state](https://html.spec.whatwg.org/multipage/input.html#text-(type=text)-state-and-search-state-(type=search)). Само решение ограничить имя — выбор продукта, а не требование стандарта HTML.

## Что обновлено

- directory-records: корректность Unicode, однострочное имя и сценарии ошибок.
- directory-access: вставка некорректного имени и незавершённое тело ответа.
- durable-storage: повреждение при читаемой схеме.
- design.md: конкретные проверки и границы браузерной метрики.
- tasks.md и CUJ: проверки новых ветвей вместе с реализацией соответствующих частей.
- ADR-0006, review.md и Fact Grounding: происхождение решения и проверенные основания.

Повторная проверка документов после правок выполнена текущей моделью. Нового независимого Goldfish GO для этой версии не заявляется. Все пять замечаний отражены в требованиях и плане проверок; открытого вопроса, мешающего начать первую реализацию, не осталось.

## Итог и следующий шаг

Пакет подготовлен к реализации с учётом перечисленных исправлений. Строгая валидация OpenSpec и проверка локальных ссылок пройдены; четыре расширенные группы экспериментов платформы прошли, результат сохранён в [JSON](../../../docs/evidence/fact-grounding-local.json).

Оценка LLM остаётся аргументированным мнением о документах. Закрытие замечаний в тексте не доказывает правильность будущего кода. Следующий этап — apply: реализовать tasks.md и выполнить предусмотренные проверки.
